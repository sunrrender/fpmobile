# FunPay Mobile (неофициальный клиент) — v0.7.0

Kotlin + Jetpack Compose + Material 3, тёмная чёрно-фиолетовая тема.
Приложение **работает в демонстрационном режиме**: все данные вымышлены, сеть не используется.

## Получение APK
Локально (JDK 17 + Android SDK Platform 35):

    ./gradlew assembleDebug
    # app/build/outputs/apk/debug/app-debug.apk

Через GitHub Actions: загрузите проект в репозиторий на GitHub → вкладка **Actions** →
**Build debug APK** → **Run workflow** (или просто сделайте push) → после зелёной сборки
скачайте артефакт **FunPayMobile-debug-apk** со страницы запуска.

## Установка на телефон
1. Скопируйте `app-debug.apk` на устройство.
2. Откройте файл и разрешите установку из этого источника.
3. Запустите «FunPay Mobile».

## Структура
- `data/` — модели, интерфейс `FunPayRepository`, `DemoRepository`, `SettingsStore` (SharedPreferences).
- `AppViewModel` — состояние загрузки/ошибки, локальные сообщения, настройки.
- `ui/theme`, `ui/components`, `ui/screens`, `ui/nav` — тема, общие компоненты, экраны, навигация.

## Интеграция с FunPay
Не реализована. Если появится официально разрешённый способ доступа, достаточно добавить вторую
реализацию `FunPayRepository` и подставить её в `AppViewModel`. Пароли, cookies и токены не должны
попадать в код, логи или чат.

## Новое в 0.5.0: вход по golden_key (неофициально)
- «Ещё» → «Подключить аккаунт FunPay»: вход по cookie golden_key вашего аккаунта. Официального API у FunPay нет, поэтому клиент разбирает страницы сайта; при изменении вёрстки функции могут сломаться. Риск ограничений аккаунта лежит на пользователе.
- Реальные данные: баланс, заказы (продажи и покупки), диалоги и переписка с отправкой сообщений, мои предложения, просмотр площадки (игры → разделы → предложения).
- Оплата и покупки в приложении не выполняются: предложения и заказы открываются на сайте FunPay.
- Ключ хранится в EncryptedSharedPreferences (Android Keystore), отправляется только на https://funpay.com, не пишется в логи.
- Без входа приложение работает в демо-режиме.

## Новое в 0.7.0
- Исправления ошибок 400 (отправка сообщения в чат) и 428 (публикация лота): запросы приведены к виду,
  который использует актуальная открытая библиотека FunPayAPI (объект `chat_node`, JSON-массив `objects`,
  все cookie сессии, `Referer`/`Origin`, повтор после обновления сессии и csrf-токена). Ошибки теперь показывают
  текст ответа FunPay, чтобы причину было видно. **Проверить на живом сайте из этой среды было нельзя.**
- Рейтинг и число отзывов продавцов в списке предложений; экран продавца с отзывами.
- «Мой рейтинг и отзывы» в профиле, ответ на отзыв (запрос `orders/review`).
- Аватарки продавцов, собеседников и своя (загрузка только с адресов FunPay, без ключа в запросах).
- Редактирование профиля и загрузка аватара внутри приложения не реализованы: для них нет проверенного способа,
  кнопка открывает настройки на сайте.
